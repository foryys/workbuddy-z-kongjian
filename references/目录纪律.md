# 目录纪律（硬上限 ＋ 建目录前先问）

> 原 SKILL.md 第七节，2026-09-20 迁出（v0.8.0）。**原文未改**，另补 2026-09-18 实例。
> 触发：「目录太多了」「文件夹太多」——**先给他看现状数字，别直接动手**。

**为什么单列一节**：项目做大时**目录比文件更容易失控**。实测一个项目 **146 个目录**，其中 **136 个挤在 `.workbuddy`**，
`ppt-master` 一个就占 **112 个**（3 个工作区 × 各自 30~60 个子目录）。用户的原话是"**文件夹太多了**"。
目录一多，找东西靠翻、助手每轮扫目录也变慢。

## 硬上限（超了当场归位）

| 层                 | 上限                  | 内容                                                                                                                             |
| ----------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **项目根**           | **一级目录 ≤3 ＋ 文件 ≤6** | `archive/`（归档）· `output/`（成品）· `.workbuddy/`（内部件）。根下的文件**只准视图与入口**：`看板.html`／`WORKBUDDY.md`／`.gitignore`／`README`——**不落任何过程文件** |
| **`.workbuddy/`** | **固定 4**     | 固定：`memory/` `rules/` `tmp/` `tools/`。`tmp/` ＝ 用完即弃（收尾后 0 件）；`tools/` ＝ 长期脚本与工具工作区（如 `ppt-master/`）。**不再有内部 archive／专题目录**              |
| **`archive/`**    | 不设上限，**但只准平铺**      | **只在项目根**，一律 `专题-<主题>-YYYYMMDD/`（＋ 暂存区 `待回收-<范围>-YYYYMMDD/`）                                                            |

## 三条动作纪律

1. **建目录前先问**——先说清"我要建 `xxx/`，放 <什么>，为什么不能挂到已有的 `yyy/` 下？"，**用户点头才建**。
   **默认答案是"挂到已有目录下"**：专题过程件 → `archive/专题-XXX-日期/`；本轮脚本与当期过程件 → `tmp/`。
2. **一个用途一个目录，不按轮次／按页／按版本新建**——`P09/`、`round2/`、`v3/` 这类临时分组**不许出现在顶层**
   （要建就建在 `tmp/` 里，随收尾一起清）。
3. **工具自建的多层中间目录**（`ppt-master` 这类）**算"一个目录"**，但**每个项目只留当前一份工作区**；旧工作区归档或删，不留第二份。

## 任务文件夹怎么命名（2026-10-13 用户定）

**`output/` 下每个任务文件夹名 ＝ 客户端会话名**（用户界面上看到的那个名字），**不自己另起简称**。

- 会话名带**半角竖线 `|`** 的（如 `20261012|示例|PPT大纲`）—— 半角 `|` 在 Windows 文件名里**非法**，改用**全角 `｜`**（看起来一样）。
- **会话名怎么查**：`~/.workbuddy/workbuddy.db` 的 `sessions` 表，按 `cwd` 过滤本项目、`custom_title` 优先（**只读打开，别直连改**）——详见 `references/环境注意.md`。
- **散件怎么归**：收尾时看 `output/` 根上还有没有**没进任务文件夹的文件**——有就按上面查到的会话名移进去。
  查法（SQLite 只读）：

  ```python
  import sqlite3, os
  db = os.path.expanduser("~/.workbuddy/workbuddy.db")
  c = sqlite3.connect("file:%s?mode=ro" % db.replace("\\", "/"), uri=True)
  for sid, ct, ti, ca in c.execute(
      "SELECT id, custom_title, title, created_at FROM sessions "
      "WHERE cwd LIKE ? ORDER BY created_at", ("%<项目名关键字>%",)):
      print(ct or ti, sid)
  ```

  归类只**移动**，不删；移不动的不确定归属的**留在原地**并报给用户。
  `scripts/体检.py` 的「output/ 顶层散件数」会报还剩几件没归。

## 收尾时的目录体检（**跑脚本，不手算**）

```
python "<技能目录>/scripts/体检.py" <项目根>
```

五项指标：`一级目录数（≤3）／项目根文件数（≤6）／.workbuddy 顶层数（≤4）／.workbuddy 顶层散文件数（=0）／archive 顶层条目数`。
阈值只有一处来源：**SKILL 第六节「判定总表」**。

> ⚠️ **别看错**：项目根**本来就该有几个文件**（`看板.html`／`WORKBUDDY.md`／`.gitignore`／`README`）——
> **要清的是 `.workbuddy` 顶层那些散落的过程文件**（本项目曾有 10 个：`_door_*.jpg`、`tmp_*.txt`、`slide-outline.md`…）。

> 2026-09-18 实例：本项目按这三条收敛——`.workbuddy` 顶层 **19 项 → 7 项**、顶层散文件 **10 → 0**、
> 项目目录 **146 → 134**、`ppt-master` 工作区 **3 → 1**；另删 5 份旧课件大件与 1 个转换临时区（约 164 MB，全部走回收站）。
> **唯一"差点移错"的判断**：`survey/` 看似专题过程件，实为**对外投放问卷的唯一正文源** → 保留。

## 顺带：临时目录必须进 `.gitignore`

铺骨架（新项目）与升级项目时，`.gitignore` **必须**含这一行：

```
.workbuddy/tmp/
```

**归档目录整目录排除**：

```
archive/
```

（别按扩展名挡——实测按 `.pptx` 只挡住 19 个，剩下 png/jpeg/svg 近 2000 个照样入库，`.git` 被撑到 43 MB。）
**没铺 git 的项目跳过本节**（判据见 `references/新项目.md`「铺不铺 git」）。

**漏了会怎样**（本项实测）：临时件被**正常入库**——933 个过程件进了 git；`tmp` 清掉后
`git status` 冒出 **600 多条"已删除未提交"**，工作树永远脏；`.git` 被撑到 **515 MB**。
**删掉已入库的文件，必须同步 `git add -- <路径>` 把删除提交掉**，否则那份"脏"会一直挂着。
