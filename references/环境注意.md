# 环境注意（本机 Windows 实测）

> 原 SKILL.md 第八节，2026-09-20 整体迁出（v0.8.0）。**原文未改**，另补两条 2026-09-18 实测；
> 2026-09-21 又从 `project-rules.md` 第十章迁入「**卡顿与轮转**」三节（**一字未改**）—— 它们同属"本机实测"，合并成一处。
> 本文件按需查阅——**不要每轮读**。

- **Bash 的 PATH 可能整体是坏的**：`ls`／`dirname`／`head` 一律 `command not found`。
  **每次命令开头加**：`export PATH="/usr/bin:/bin:/c/Windows/System32:$PATH"`——实测这一句就能跑通。
  再不行就用 **Glob（带 `path` 参数）** 列文件、`Read`／`Grep` 读内容。
- **PowerShell 工具可能完全不回显 stdout**（连 `"HELLO"` 都不显示，退出码却是 0）——
  **别拿它当"执行成功"的证据**；改用 `Read`／`Glob` 回读确认。
- **Python 通道优先**：`"C:/Users/<用户>/.workbuddy/binaries/python/versions/3.13.12/python.exe"` ＋ heredoc，
  配 `export PYTHONIOENCODING=utf-8`。**算体积、扫目录、做统计一律走 Python，不要用 shell 拼**。
- **新建目录后先确认目录存在再写文件**；写完关键文件用 `Read` 或 `Glob` 回读。
- **git 不在 PATH**：用绝对路径 `C:\Users\<用户>\.workbuddy\binaries\PortableGit\versions\<ver>\cmd\git.exe`。
- 全局 git 身份可能为空：用 `git -c user.name="WorkBuddy" -c user.email="workbuddy@localhost" commit …`；
  **不擅自改全局配置**。
- **走回收站**（「清空重做」「瘦身」必用）：`rm -rf` 禁用。写法与**六个坑**见 `references/接手项目.md` 的
  「Windows：怎么真正走回收站」——**别用 ctypes 直调、也别 Add-Type，直接引用 `Microsoft.VisualBasic.FileIO.FileSystem`**；
  **判成败只看结果（源目录归零 ＋ 回收站有 `$I`/`$R` 成对条目），不要看 `try/catch`**（2026-09-20 补）；**删目录时它还会假报「这个系统不支持该功能」，内容其实已入站**（2026-09-20 补）。
  **`$I` 怎么读**（2026-09-29 实测，此前读成乱码浪费 4 次）：**路径在偏移 28**（前 4 字节是名称长度，按 UTF-16LE 解；用偏移 24 解出来全是乱码）；**`$I` 文件的 mtime ＝ 删除时刻** → 按"最近 N 分钟"筛一遍最省事。删 D 盘的东西，`$I` 在 `D:\$Recycle.Bin\<SID>`（**不是 C 盘**）。
  ⛔ **绝不在回收站调用后写 `Remove-Item -Recurse` 兜底**——真没进站时会**硬删**；兜底只允许 `rmdir`（仅删空目录）。
  ⚠️ **2026-09-18 实测更正**：该类型**只有 WorkBuddy 的 PowerShell 通道能引用**；经 Python `subprocess` 直接调
  `WindowsPowerShell\v1.0\powershell.exe` 会报 `TypeNotFound`（改用 `-EncodedCommand` 也一样）。**不要绕道去调那个 exe。**
  另：**PowerShell 工具报 exit 1 多为误报**——实测删除已完成却返回 1。**是否生效一律从 Bash 侧复核**（列目录／算体积）。
- **批量删除前逐字核对文件名**：写错一个字就 `Test-Path` 为 false 被**静默跳过**（本项目曾把 `_20260916` 写成 `-20260916`，漏删一份）。**删除后必须回读目录复核。**
- **bash 会展开命令里的反引号与单引号包裹的内容**：把含反引号或 `'XML 片段'` 的文本塞进 `python -c "…"`，会被 shell 当命令执行，报 `xxx: command not found`，**写进文件的内容残缺**。→ **长文本一律先 `Write` 成文件再读**，不要塞进 `-c`。
- 往 `%TEMP%` 落盘会静默失败——临时数据用 Python 在内存里处理。
- ⛔ **禁止对 git 仓库做任何维护操作 —— `gc`／`repack`／`prune`／`prune-packed` 全部禁用**（2026-09-20 **同日两次真实事故**）。两次都把 `.git/objects` 清空（`git log` 报 `fatal: bad object HEAD`）：第一次 `git gc`（未备份），第二次 `repack -a -d`（**已先做 .git 全量备份**，仍然清空）。
  **根因（本机实测）**：这台机器上 git 的删除**不落盘 unlink，而是进回收站** —— 维护操作依赖的"删旧留新"在本机行为不可控。
  **两次都救回**：① 解析回收站 `$I` 元数据取回原始路径（`<项目>/.git/objects/xx/<38位>`）逐个复制回原位；② 直接从 49 秒前做的 `.git` 全量备份复制 `objects/` 回来。
  → **本机规矩：`.git` 多大都不清**（D 盘空间充足）；真要瘦身去别的机器做，且**必须先全量备份**。
  → 给 git 传中文路径一律走 Python `subprocess`（参数不经 shell）。
- ⛔ **「上一轮改完核对通过」≠ 文件现在还是那样**（2026-10-08 实战）：本轮动手前读到的 `SKILL.md` 是好的，
  动手后官方机检却报 **`No YAML frontmatter found`** —— 文件**已被改坏**（`---`→`\---`、汉字变 HTML 实体、表格被重排、行尾灌空格，
  另有一处内容被吃掉半截），而且坏法与本文件已记的四种破坏**完全同一批**。
  → **两条硬动作**：① **动手前先备份一份带时间戳的**（`SKILL.md.bak_修复前_<时间戳>`，本次靠它复核与回滚）；
  ② **收工前跑一次官方 `quick_validate.py`，别只跑自己写的体检脚本** —— 体检脚本查不出 frontmatter 被转义。
  **自查要问的是「现在这份文件过没过机检」，不是「我上次跑过没过」。**
- ⚠️ **回收站调用后必须从 Bash 侧复核源目录**（2026-10-08 补）：PowerShell 报 exit 1（见上，多为误报），
  源目录确已归零 —— 但**回收站里没查到对应条目**（`$I` 总数 0，可见 `$R` 内容项 28,286，glob 未命中 `$I`）。
  **判据收紧为「源路径消失 ＋ 回收站按原始路径查得到」，两条都满足才算进站**；只满足前一条时，
  必须**另留一份可回滚副本**，并在汇报里说清"已清、原件在某某处"。
  另：`Add-Type -AssemblyName Microsoft.VisualBasic` **被本机安全策略拦**（"compiles and loads .NET code at runtime"），
  **但该类型无需 `Add-Type` 即可直接引用** —— 直接写 `[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile(...)`。
  ✅ **2026-10-13 订正：这条路是通的 —— 此前"三条全被拦、不要再试"是误判，已作废。**
  **真相**：当天**回收站堆到了上限（19.2 GB）** —— **超限后新删文件不进站、直接永久删除**，看着像"通道被拦"，其实是"站满了"；清空后同一条调用一次成功。
  **终验结论**（`~/.workbuddy/KNOWLEDGE.md` §五）：**走回收站可做，已确证真进站**。三个必要条件：
  ① **直接引用**写法 `[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile(p,'OnlyErrorDialogs','SendToRecycleBin')`（**加 `Add-Type` 必被拦**："compiles and loads .NET code at runtime"）；
  ② 走 **WorkBuddy 的 PowerShell 工具通道**（从 Bash／Python `subprocess` 调 `powershell.exe` 会被拦）；
  ③ **回收站没满** —— 最容易漏的一条：**满了会静默永久删除**，用前先确认。
  **确实走不通的两条**（这两条是真的）：`pythonnet` 的 `import clr`（无此模块）／`New-Object -ComObject Shell.Application`（COM 实例化被拦）。
  **配套口径**（不变）：删除前「**先落一份清单（路径／大小／MD5）＋ 向用户说明 ＋ 取得明确同意**」。

- ⛔ **预览页面里点不开任何本地文件／文件夹**（2026-10-13 实测 ＋ 查客户端代码确认）：**WorkBuddy 预览面板拦截一切非 http／https 导航**
  —— 客户端日志原文 `Blocked non-http child-window navigation`；页面侧也**没有**可调用的"打开路径"接口
  （`openPath`／`showItemInFolder` 只挂在主进程 IPC 上，暴露给页面的只有日志／遥测／腾讯文档沙箱的 `mqq`）。
  **四种写法实测全失败**：普通 `<a href="file:///…">` ／ `target="_blank"` ／ `window.open()` ／ 直接 `location.href`。
  → **结论**：看板**别做「产物入口／打开文件夹」栏位**；要看文件夹只有两条路 —— **本地双击 .html 用系统浏览器打开**，或让用户**复制路径**粘贴。
  → 另：预览服务**只服务 `.html` 文件**（探针实测：新建 html 立刻 200、同名 md 是 404）——所以也别指望"链到 md／pptx"或"生成中间页"。

- **查客户端会话名**（给 `output/` 任务文件夹命名用；2026-10-13 实测）：客户端数据库 **`~/.workbuddy/workbuddy.db`**（SQLite）。
  表 **`sessions`** 关键字段：`cwd`（项目路径）／`title`（自动生成名）／`custom_title`（用户改的名，可为空）／`last_activity_at`（毫秒时间戳）。
  取法：按 `cwd LIKE '%<项目文件夹名>%'` 过滤 → **`custom_title` 优先、`title` 兜底** → `ORDER BY last_activity_at DESC`。
  **只读打开**：`sqlite3.connect('file:C:/Users/<用户>/.workbuddy/workbuddy.db?mode=ro', uri=True)`；
  **别直连改**它（自动化任务另有明文禁令）。另有两表可顺手查：`workspaces`（项目路径／最后打开时间）、`session_usage`（用量）。
- **改 `.md` 一律 `newline=""` 读、`newline=""` 写**（2026-09-18 补）——否则 CRLF 被改写成 LF，整个文件在 git diff 里飘红，真假改动分不出来。
- **同一文件的多处 `Edit` 会互相吞改动**（2026-09-18、2026-09-20 **两次**复现）——后一处覆盖前一处，**工具仍报成功**。
  → **一处以上就用脚本一次做完 ＋ 逐条断言**（读入 → 逐条 `replace` 且 `count(old)==1` → 写盘），改完**通查关键串是否都在**。
- **中文文件名里的英文词拼错会伪装成"文件不存在"**（2026-09-18 补）——`CIOE` 被写成 `CIEO` 时，报错形态与"文件缺失"完全一样。→ 自造文件名加 `assert os.path.exists()`，或先 `Glob` 确认。

## 卡顿与轮转（本机实测 · 2026-09-21 自规则第十章迁入）

### 卡顿从哪来（2026-09-16 本机实测）

| 观测点 | 实测值 | 含义 |
|---|---|---|
| 单会话转录 | 最长 **22.4 MB / 2721 条** | 切回该会话要全量读盘 ＋ 逐行解析 |
| **转录构成** | **工具调用＋结果 77.1%**；真正的对话内容只 **6.5%** | "没聊几句却很卡"的真相：**膨胀的是工具调用** |
| 工作进程 | **19 个 / 3.1 GB**（单进程峰值 1275 MB） | 活跃会话数 ≈ 常驻进程数 |
| `traces/` | 420 目录 / **1297 MB** | 历史执行轨迹（可回查），**不整体删** |
| `workbuddy.db-wal` | 1.02 MB | **重启客户端**即回收（不要手动 checkpoint） |

**一句话**：这套技能每多做一次读写，转录就多两条记录。**所以"少调用"就是治卡顿。**

### 轮转线（本机实测判据）

| 触发条件 | 动作 |
|---|---|
| 单会话转录 **> 20 MB** 或 **> 5000 条** | 立刻收尾，**开新对话**接着做 |
| 一个对话跑满 **10 轮** | 同上 |
| 同时开着的会话窗口 **> 2 个** | 关掉不用的（每个活跃会话占一个常驻进程） |
| 感觉卡 | 跑 `工作空间优化/scripts/体检.py <项目根>` 看体积 ＋ 按上面两条轮转线自查（**已不依赖外部技能**） |

### 要主动提醒用户的三件

1. **只留 1~2 个会话窗口**；不用的关掉，立刻减负。
2. **卡了就重启客户端**——回收 WAL、清内存（实测重启后 WAL 从 MB 级降到 0.03 MB 左右）。
3. 归档件在项目 `archive/` 下（**不再有 `_attic/`**），确认几天没问题后按「目录纪律」清退——**只移动；删除先出清单让用户点头**。
