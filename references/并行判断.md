# 并行判断

**动手前先判有没有别的会话在同一个工作空间里跑。** 尤其删除、覆盖、大范围移动之前——判错一次就可能删掉别人正在用的东西。

## 一、三步取证

| # | 查什么 | 怎么看 |
|---|---|---|
| 1 | `git status --short` | 有**你没做过的成品改动** → 停手问用户。没铺 git 的项目改看文件 mtime |
| 2 | 比对目录内文件 mtime | 找出**你没做过的产出**（归档件、成品） |
| 3 | 看 `tmp/` 里有没有陌生脚本名 | 如 `build18b/`、`deploy_p20.py` —— `tmp` 很可能正是对方的工作区 |

**三证齐 ＝ 确认并行。删除类操作一律暂停**，等用户明确「那边已结束」再动。

**只有一证时**：可以继续，但凡是**覆盖、删除、大范围移动**都先问一句。宁可多问一次。

## 二、判断的边界

- 判据是「有没有我没做过的改动」，**不是「文件新不新」**——你自己刚写的也新。
- `git status` 干净**不等于**没有并行：没铺 git 的项目、或者对方还没写盘，都看不出来。所以要看 mtime 与 `tmp/`。
- 发现并行后**不要试图协调**——你不知道那边在做什么，也不知道它什么时候结束。报给用户，让用户定。

## 三、提醒项不在这里

用户要求「以后每次都要提」的事项，存进项目 `WORKBUDDY.md` 的「本工作区必提醒」节，由 `开工与收尾.md` 第一步每回合过一遍。**不靠助手记性，也不在本文件另存一份。**

## 四、复盘与沉淀不归本技能

「这几回合有没有下次还会遇到的坑」、总结经验、优化自定义指令／人设／记忆、维护经验台账——**本技能一概不碰**。

**本技能只管「项目怎么管」。**

本技能自身要改时：只有用户点头才改，改完版本 +1 ＋ `changelog.md` 记一行，并提醒已铺好的项目说一句「升级项目」才跟上。
