# 开工（每一轮开始）

**先看档位**：**单次档不用开工**（直接干活）；**轻长期档**默认也不喊口号，用户想看进度时才回三行；
只有**长跑档**默认走这一套。

四步：**看 → 提 → 说 → 等**。

## 1. 看（**有预算，别多读**）

**读入集合**（长跑档单轮合计**≤ 20 KB**）：

| 读什么 | 读多少 |
|---|---|
| `.workbuddy/rules/工作空间规则.md` | **只读「〇、每轮必读」** |
| `WORKBUDDY.md` | 全读（它很小）——**重点看「本工作区必提醒」节** |
| `看板.html` | **只看「待办清单」「未了清单」与「正在做」三块**（其余不读） |
| 记忆 | 只读 `MEMORY.md`；**日志不读** |
| `changelog.md`／素材登记 | **不读**（要用时 grep 定位） |

- 先 `git status`（**没铺 git 的项目跳过这一条**）：有未提交的改动 = 有别的对话正在写 → **停手问用户**。
- **核一次基线**：拿看板里的当前基线，和产物标注的「依据 vX」对一遍。有产物落后，写进"风险"行。
- **顺手核对看板有没有落后**（2026-09-21 加）：拿看板三块（**主线**／**要做的事**／**已定事项**）跟磁盘上的真实状态对一遍，**落后的当场补齐再报进度**——别只报"看板是旧的"。
- 轻长期档只有 `看板.html`，读它即可。

## 2. 提（**必提醒——先提，再说进度**）

**提醒从哪来**：项目的 `WORKBUDDY.md` → **「本工作区必提醒」**节——这里放**用户要求"以后每次都要提"**的事项
（例：阶段性复盘会、某份产物到期复核）。**该节不存在 → 说明本项目没登记过长期提醒，别自己编一条。**

- **怎么判断该不该提**：按该节每条写明的**触发点**（如"新对话第一轮""用户说开工""阶段收口时"）逐条比，命中就提。
- **每处只提一次**——用户没接话就不追、不重复、不打断当前任务。
- **只提一句**，不要写成任务列表，也不要在同一轮把同一件事提两遍。

## 3. 说（三行 ＋ 一行提醒）

```
进度  第 2 轮 ｜ 做完 4/9 步 ｜ 正在做：生成第 1 讲课件
待办  等您回传素材
风险  演示页视频会随页序移动，重导后需重插
提醒  阶段收口了，要不要开次复盘会？（第 2 步命中时才有这一行）
```

- 步骤**说中文全名**，不要只说编号；有卡住的写清**在等什么**。
- 基线落差写在"风险"行，点出哪几件产物落后于哪一版。
- 需要用户拍板的单独列出。**正文不超过三行**（提醒单独一行，不算在内）。

## 4. 等

**用户没确认前不动手。** 不自动开始下一步，不一次抛多个问题。

## 禁止

- 不产出业务成品。
- 不自己把"等验收"改成"已完成"。
- 不重排步骤编号。
- **不整份读累积型文件**（记忆日志）。
- **不把提醒变成自动执行**——"要不要开复盘会"是**问**，不是**开**。
