# 判据与阈值

**项目侧所有可判数字只看这一份。** 技能自身的体量上限在 `SKILL.md` 第六节，不在这里。

> 两处并存不是重复：这份管「项目里长什么样算超标」，`SKILL.md` 管「技能自己多大算超标」。另一个独立副本在 `project-rules.md`——那份会复制进项目，项目里没有技能目录，必须自包含。

## 一、目录与项目根

先定分型，再判数。**分型只决定一件事：数不数一级目录个数。**

| 型 | 判据（根下有任一即是） | 怎么判 |
|---|---|---|
| **文本型** | —（默认） | 一级目录 **≤3**（`archive/`／`output/`／`.workbuddy/`）＋ 根文件 **≤6** |
| **代码型** | `go.mod`／`package.json`／`*.sln`／`*.csproj`／`pom.xml`／`requirements.txt`／`Cargo.toml`，或有 `src/`／`bin/`／`dist/`／`app/` | **不数目录个数**。改判：源码夹与构建产物夹各一个、名字固定、不另起同类；根散文件 ≤6；`archive/`／`output/`／`.workbuddy/` 照样要有 |

判错了两边都能用 `--type text` / `--type code` 覆盖。脚本会自动认，认不准时手动指定。

**根下只放视图与入口**：`看板.html`／`WORKBUDDY.md`／`.gitignore`／`README`。**不落过程文件。**

## 二、`.workbuddy/` 内部

**顶层固定 4 个**：`memory/`（客户端自带）／`rules/`／`tmp/`／`tools/`。

- `tmp/` ＝ 用完即弃，**收尾后 0 件**
- `tools/` ＝ 长期脚本与工具工作区（如 `ppt-master/`）
- 不设内部 archive／专题目录

**`archive/` 只在项目根，只准平铺**：一律 `专题-<主题>-YYYYMMDD/`，暂存区一律 `待回收-<范围>-YYYYMMDD/`。不嵌套、不按轮次分。

## 三、体量

| 判什么 | 阈值 | 超了怎么办 | 谁执行 |
|---|---|---|---|
| 项目记忆 `memory/MEMORY.md` | **3000 字符** | 会被**静默截断**。迁出不是删：技术结论 → 冷区 `~/.workbuddy/KNOWLEDGE.md`；历史留档 → `archive/专题-日志归档-*/`；**原位留一行「已迁出 → 去哪」** | 收尾／瘦身 |
| 用户级记忆 `~/.workbuddy/user-<uid>-<企业id>/MEMORY.md` | **4000 字符** | 同上。先删过时／废条目，再考虑移冷区 | 收尾／瘦身 |
| 日志 `memory/YYYY-MM-DD.md` | **8 KB** | 全文归档（一字不改）→ 换精简版 | 收尾 |
| `看板.html` | 不设阈值 | 只保留仍生效的；旧条目攒到 **10 条以上**清退一批 | 收尾 |
| 单轮读入合计 | **20 KB** | 只读"必读节" | 开工 |
| 项目内要读的文件 | 规则各 **24 KB**（必读段 **2 KB**）· `WORKBUDDY.md` **6 KB／60 行** | 按工序拆文件；抬头写明读法 | 收尾 |
| 归档单件 / 同类份数 | **>10 MB** 或同类多份 | **归档前先问用户** | 归档前 |

## 四、文件去留五判据

按顺序问，任一「否」就按结论处置。**默认留，不默认删。**

| # | 问 | 是 → | 否 → |
|---|---|---|---|
| 1 | 它回答的问题，别的文件是不是已经回答过？ | **不新增**，改那份已有的 | 问 2 |
| 2 | 它是「给用户看的」还是「助手用的」？ | 给用户看 → 进看板或产物 | 助手用 → 进 `memory/` 或 `.workbuddy/` |
| 3 | 它是不是还挂着一件没做完的事？ | 留 | 归档；再没人动 → 回收站 |
| 4 | 它是记录还是工具？ | **工具不参与判断**（不进上下文、不产文件、留着不占地） | 记录 → 问 5 |
| 5 | 删之前答得出「丢了它，下次接续会缺哪句信息」吗？ | 答得出 → 才允许删 | **答不出 → 不许删** |

**判据 3 不许改成「多少天以后还会有人看」**——那是预测未来。**删除只发生在收尾**：定时清理永远不会发生，而没干活就不会有新垃圾。

## 五、归档规则不在这里

**归档件守哪三条、快照留几份、怎么送回收站** → 全在 `删除与归档.md`。归档是「删东西」这一类动作，规则跟着动作走，不在本文件另存一份。

## 六、建目录前先问

**默认答案是「挂到已有目录下」**。要建新目录，先说清「我要建 `xxx/`，放什么，为什么不能挂到已有的 `yyy/` 下」，用户点头才建。

- 不按回合／按页／按版本建目录。`P09/`、`round2/`、`v3/` 这类临时分组**不许出现在顶层**——要建就建在 `tmp/` 里，随收尾一起清。
- 工具自建的多层中间目录算「一个目录」，但**每个项目只留当前一份工作区**。

## 七、超了怎么处置（三分支）

| 情况 | 动作 | 边界 |
|---|---|---|
| 位置不对 | **归位**：移进已有目录 | 只移动，不改名、不重排 |
| 体量超了 | **瘦身**：迁出到冷区或归档 | 先删过时条目，再考虑迁出；原位留指路行 |
| 不再需要 | **清退**：移进暂存区 `archive/待回收-<范围>-YYYYMMDD/` | 只移动；送回收站另走确认 |

**跑一次全出来**：

```
python "<技能目录>/scripts/体检.py" <项目根>
```

打印 A 目录五项 ＋ B 体积六项，不合格项标 ⚠️。禁止手算。

## 八、卡顿与换会话

**判据是本地读盘与进程内存，不是上下文窗口。** 转录越长，切回该会话越慢——所以「少调用」就是治卡顿：转录里四分之三是工具调用，真正的对话内容只占几个百分点。

### 什么时候该换会话

| 触发 | 动作 |
|---|---|
| 单会话转录 **> 20 MB** 或 **> 5000 条** | 立刻收尾，**开新会话**接着做 |
| 一个会话跑满 **10 回合** | 同上 |
| 同时开着的会话窗口 **> 2 个** | 关掉不用的（每个活跃会话占一个常驻进程） |
| 感觉卡 | 先跑 `scripts/体检.py` 看体积，再按上面三条自查 |

### 要主动提醒用户的三件

1. **只留 1~2 个会话窗口**，不用的关掉，立刻减负。
2. **卡了就重启客户端**——回收 WAL、清内存。
3. 归档件在项目 `archive/` 下，确认几天没问题后按 `删除与归档.md` 清退。

**这三件是提醒，不是自动执行**——关窗口、重启都等用户点头。
