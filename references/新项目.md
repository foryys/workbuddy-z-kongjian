# 新项目：三步开干

> **规则和模板都在本技能目录里**：`references/project-rules.md`（规则原件）＋ `assets/`（模板）。
> 铺项目时直接复制过去，**不需要配任何路径**。

## 第 1 步 · 确认空文件夹，说一句话

在 WorkBuddy 新建工作空间，选一个**空文件夹**当项目根。
**不要先往里面建文件**——骨架由模板生成，手工建的会跟模板打架。

然后用户说一句：**「启动项目：<项目名>」**

## 第 2 步 · 回答两个问题 → **按最低档起步**

一次问一个：

**1.「这事做一次就完，还是以后会反复改？」**

| 回答 | 档位 | 铺什么 | 每轮要做什么 |
|---|---|---|---|
| 做一次 | **单次（默认）** | **只有 `output/`**，不铺骨架、不建 git | **零仪式**——做完直接给用户看 |
| 会改几轮 | **轻长期** | `看板.html` ＋ 规则副本 | 产物 ＋ 刷看板 |
| 长期迭代 | **长跑** | 再加 `WORKBUDDY.md`、git（记忆走原生 `.workbuddy/memory/`，**不用铺**） | 上表 ＋ 拍板即落看板 ＋ 每轮换对话 |

**默认从最低档起步**：用户拿不准就先按"单次"做——他没有记录负担，你也不用维护一堆文件；
真需要长期了再加档（"升成长跑档"），**不重做已有内容**。
**反过来（不问就铺全套）是错的**，那正是这个技能最容易被抱怨"繁琐"的地方。

**2.「手上已经有东西了吗？」**
- 空手 → 继续往下
- 有资料 / 有旧项目 → **转「接手项目」**，不铺新骨架

### 铺之前，先过「减件关」（规则第二章）

| # | 问自己 | 结果 |
|---|---|---|
| 1 | **这条信息除了它还有谁记？** | 有人记了 → **不铺** |
| 2 | **用户会看它吗？** | 不会看 → 放 `.workbuddy/`，不放项目根 |
| 3 | **它是最终交付，还是中间件？** | 中间件 → 放 `.workbuddy/`，不进 `output/` |

**一条线只交一件主产物。** 例：做一讲课件，主产物就是那份 `.pptx`；
课程内容大纲、分页结构、制版规格这些**都是中间件**，放 `.workbuddy/`，不进 `output/`。
用户要额外交付物时再给，**不主动多产出**。

**取件对照表**（全部来自本技能目录）：

| 本技能里的 | 铺到项目哪里 | 哪个档 |
|---|---|---|
| `references/project-rules.md` | → `.workbuddy/rules/工作空间规则.md`（复制并改名） | 轻长期、长跑 |
| `assets/看板.html` | → 项目根 `看板.html`（**唯一给用户看的治理文件**） | 轻长期、长跑 |
| `assets/WORKBUDDY.md` | → 项目根 `WORKBUDDY.md`（内部件） | 长跑 |
| `assets/工作空间规则-本项目.md` | → `.workbuddy/rules/工作空间规则-本项目.md`（**只在"要推翻通用规则"时**才给；一般项目约定写进项目记忆，**不铺这个文件**） | 任意 |
| **`.gitignore`**（手工建，不是模板） | → 项目根 `.gitignore`，**长跑档且铺 git 的项目必做** | 长跑 |

### 骨架最后一件（30 秒，做完才算铺完；**没铺 git 的项目跳过本节**）：`.gitignore` 排除临时目录

项目根建 `.gitignore`，**至少含这一行**：

```
.workbuddy/tmp/
```

**漏了会怎样**（实测）：临时件会**正常入库**——本项目 933 个过程件进了 git；清掉 `tmp` 后
`git status` 冒出 **600 多条"已删除未提交"**，工作树永远脏，`.git` 被撑到 **515 MB**。
**删掉已入库的文件，要同步 `git add -- <路径>` 提交删除**，否则那份"脏"一直挂着。

**产物怎么命名**：一个东西**一个文件**，改就在里面改——版本号写在**文件里面**（标题旁或页脚），
**不写进文件名**；目录也不带版本号（用 `output/第1讲/`，不用 `output/v0.1/`）。旧版靠存档找回。

**目录怎么建（硬上限，详见 `references/目录纪律.md`）**：项目根 **一级目录 ≤ 3**（`archive/`／`output/`／`.workbuddy/`），
根下**不落过程文件**；`.workbuddy/` 下**固定 4**（`memory/` `rules/` `tmp/` `tools/`）；**建新目录前先问用户**，默认挂到已有目录下
（专题过程件 → `archive/专题-XXX-日期/`，本轮脚本与当期过程件 → `tmp/`）。

## 第 3 步 · 长跑档答四个问题 → 开新对话说「开工」

**单次档跳过这一步**；轻长期档只需要第 4 问。

一次问一个：

1. 这个项目**要做成什么**（一句话，可验收）
2. **绝不做什么**（至少两条）
3. 验收标准：谁验收、什么叫做完
4. 第一轮做什么，并写明**本轮不做什么**

问完复述一遍给用户确认。**这一步不产出任何业务成品。**

### 铺不铺 git？先过这一条判据

**问一句：这个项目里"要反复改的文本"占多少？**

- **文本为主**（规则、方案、文档、代码）→ **铺 git**：价值在版本回溯上。
- **设计／大件为主**（PPT、图片、视频）→ **不铺**：实测这类项目 5 次提交 **0 次回滚**，提交文件里 **97%** 是 png/jpeg/pptx 大件，`.git` 白涨 43 MB。
  **替代方案**：成品**按时间戳另存、不覆盖**（`exports/xxx_123416.pptx`），源件另有 `backup/<时间戳>/` 快照 → 天然留每一版，不需要回滚。
- **没铺 git 的项目**：`.gitignore` 不用建；开工跳过 git 三查；收尾跳过 git 存档。

**顺手定基线**（这个项目若会有"总纲"这类文件）：
指一下哪几份算**基线文档**——会被反复修订、而且下游有东西依赖它的（总纲 / 需求基线 / 规范）。
**只有它们带版本号**（写在文件里面，不写进文件名），改版走「升版三动作」；其余产物不标版本。

确认后：**开一个新对话（或重启客户端）**，在里面说 **「开工」**——能报出进度条，就说明一切生效了。

之后每轮：

| 档 | 每轮怎么说 |
|---|---|
| **单次** | **不用说**——直接要东西 |
| **轻长期** | 直接干；想看进度说「开工」，收尾说「收尾」 |
| **长跑** | 「开工」→ 干活 → 「收尾」，**收尾就该换对话了** |

## 遇到这些情况怎么做

| 情景 | 用户怎么说 | 会发生什么 |
|---|---|---|
| 一开始选了单次，后来发现要长期改 | 「升成长跑档」 | 补铺骨架（规则副本、看板、`WORKBUDDY.md`、git），不重做已有内容 |
| 想加一步 | 「第 3 步后面加一步：XXX」 | 直接加，**看板记一笔**原因 |
| 某步做不动 | — | 标 `[!]` 并写清"在等什么"；用户说「先跳过」就调整 |
| 想知道做到哪了 | 打开 `看板.html`；或说「开工」 | 看板每轮刷新；「开工」回三行 |
| 这轮完事了 | 「收尾」 | 走「收尾」那一节，并提示换对话 |
| 文件太长、越来越慢 | 「瘦身」 | 超上限的文件归档，只移动不销毁 |
| 想改目标或边界 | 「目标改成 XXX」 | 改 `WORKBUDDY.md`，并看板记一笔 |
| 想清空重来 | 「清空重做」 | 转「接手项目」最后一节（先出清单确认） |
| 名词敲不出来 | 直接说人话（「开工吧」） | 一样触发，不用记命令 |
